# F-20261010-01 — Release v0.3.0 Tag

**Date:** 2026-10-10 **Status:** Implemented
**Area:** git tags / release

## Context

The last tagged release was `v0.2.0` (2026-09-15). Since then, `main` accumulated a full
roadmap wave of features and hardening without a release cut: product repositioning
(CR-20261003-01), configuration mode hierarchy (CR-20261003-02), durability guarantee
claim precision (CR-20261006-01), non-zero CLI decode exit codes on untrustworthy
recovery (CR-20261007-01), golden vectors + `ytahd inspect` (CR-20261007-02), transit
harness scaffolding (CR-20261007-03), streaming memory-bounded durability decode
(CR-20261007-04), cross-release compatibility fixtures (CR-20261008-01), benchmark
regression guardrails (CR-20261009-01), and a containerized reproducible FFmpeg test
environment (CR-20261009-02). A new tag also gives RM-12 one more era to pin with
release fixtures.

## Decision

Tagged `v0.3.0` on `main` and pushed, triggering the tag-gated release workflow
(`F-20260903-03`): full test suite in CI, self-contained single-file CLI publish for
`win-x64` and `linux-x64`, GitHub release with both archives.

Version chosen as a **minor bump**: user-visible behavior additions (inspect command,
streaming durability decode, exit-code semantics) with wire-format continuity — v0.2.0
fixtures keep decoding (verified by `ReleaseCompatibilityTests`), so no major bump.

## Consequences

- Established the fourth compatibility era for `generate-release-fixtures.ps1`
  (after v0.1.1, v0.1.3, v0.2.0); a future run pins v0.3.0 fixtures.
- Tag-gated workflow published the binaries automatically; FFmpeg remains a separate
  prerequisite, not bundled.
- Full suite green at the tagged commit: 390/390 passed (Release, real FFmpeg).
