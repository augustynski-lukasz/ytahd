# CR-20261008-01 — Cross-release compatibility fixtures (RM-12)

**Date:** 2026-10-08
**Status:** Implemented
**Area:** `scripts/generate-release-fixtures.ps1` (new),
`YTAHD.Tests/ReleaseFixtures/` (new fixtures),
`YTAHD.Tests/ReleaseCompatibilityTests.cs` (new)

## Context

RM-11's golden vectors pin the *current* wire format, but they are generated by the
current encoder — they prove the format didn't drift since the fixture was written, not
that the decoder still reads streams produced by *prior releases*. RM-12's story:
compatibility must be proven against history, not just the current pair. The repo has
five release tags spanning three wire-format eras.

## Decision

- **Fixtures are produced by the tagged release's own code, not re-encoded by HEAD.**
  `scripts/generate-release-fixtures.ps1` extracts each tag's durability Core subset
  (`git show <tag>:path`), compiles it into a throwaway generator project, and runs the
  tag's own `DurabilityTransportCodec.EncodeToFramePackets` on deterministic payloads
  (`byte[i] = (i*11+3) % 251`, same recipe as RM-11). The emitted hex fixtures + JSON
  sidecars are committed under `YTAHD.Tests/ReleaseFixtures/<tag>/`.
- **Per-tag API surface is pinned by the generator program.** Each tag gets its own
  generator `Program.cs` using only the encoder signature that release actually exposed:
  - `v0.1.1`: v1 packets (51-byte header, 16-bit payload length), durability matrix,
    no manifest — `EncodeToFramePackets(byte[])`; fixtures `v1-256b`,
    `v1-200b-partial-group` (partial final group: 7 symbols, last group holds 3 of 4).
  - `v0.1.3`: v2 packets (53-byte header, 32-bit payload length), no manifest —
    fixture `v2-nomanifest-256b`.
  - `v0.2.0`: v2 + `StreamManifest` (start/end copies) — fixtures `v2-manifest-256b`
    and `v2-manifest-256b-chunked` (64-byte frame capacity, chunked manifest).
- **`ReleaseCompatibilityTests` decodes every fixture with the current code** via
  `TryDecodeFramePacketsWithHoles` (the real pipeline's path): strict per-packet decode,
  byte-exact payload equality, empty hole map, and (v0.2.0) manifest field reconciliation.
  One test additionally pins the hole-tolerant contract for v1 streams: truncating a
  v0.1.1 stream's final group yields a zero-filled hole + reported group id, not a
  decode failure (the v1 era predates manifest-clamped finalize holes, but the current
  decoder's contract must still hold for old streams).
- **Maintenance rule** (documented in the script and test class): when a new tag is
  released, add its fixture set + a decode test in the same change. When a wire-format
  change lands intentionally, the OLD fixtures stay — a failing decode test means
  backward compatibility broke and needs an ADR + RM-19 spec note (or a protocol-version
  gate).

## Consequences

- Backward compatibility is now a regression-tested property across all three wire-format
  eras, satisfying RM-12's acceptance ("at least the previous tagged release's fixtures
  decode correctly" — exceeded: three releases, five fixture sets, seven tests).
- The generator script is deterministic and re-runnable; regenerating must produce
  byte-identical fixtures (any diff is a signal the tag's encoder changed — impossible
  for a fixed tag, so a diff means the script's extraction broke).
- Known limitation: fixtures cover the durability packet layer, not full video
  round-trips (old tags' full encode paths depend on SkiaSharp/MathNet and are not
  rebuilt here). The packet layer is where the wire format lives; video-container
  behavior is covered by the real-codec suite at HEAD.
- The durability Core subset compiles standalone (no SkiaSharp/MathNet dependency),
  which is what makes per-tag extraction cheap.
